# DrishtiSR frontend

Demo UI: Vite + React + TypeScript, MapLibre GL JS, Tailwind. **Day 3 status:
static and mocked.** There is no backend; `src/api/client.ts` answers from
fixtures while `MOCK_MODE` is on.

```
cd frontend
npm install
npm run dev          # http://localhost:5173
npm run dev:lan      # same, exposed on the LAN for testing on a phone
npm test             # unit tests (vitest): tile-count arithmetic, the budget
npm run test:e2e     # real Chrome: swipe by mouse AND touch, AOI, badge
npm run build        # typecheck + production bundle
```

## Routes and design system

- `src/routes.ts` is the site map: one list drives both the router
  (`src/main.tsx`, react-router) and the sticky top nav (`src/layout/`).
- `/` is the Home page (`src/pages/HomePage.tsx`): hero, upload + swipe viewer
  with zoom lightbox, per-image metrics, novelty cards, impact strip. Its
  upload talks to the MVP API (`app/server.py`, `POST /api/upscale`) through
  the dev proxy (`frontend.api.proxy_target`; override with
  `DRISHTI_API_TARGET` when serve.py picks another port). The result lives in
  `src/state/ResultContext.tsx` so every page can read "this image".
  Repo-wide numbers come from `src/data/facts.ts`, which `tests/facts.test.ts`
  checks against the reports. `npm run test:e2e:home` (add `E2E_LIVE=1` to hit
  the live API) drives it in Chrome.
- `/novelty/spectral` `/novelty/uncertainty` `/novelty/efficiency`
  `/compare` `/about` are placeholders until page content lands.
- `/demo` is the full-screen map demo (the old `/`), which `npm run test:e2e`
  exercises. `/design` is the component reference (sample numbers only).
- Tokens (colour, type scale, spacing, radii, shadows/glows, motion) live in
  `src/index.css` `@theme`. Components live in `src/components/ui/`: StatCard,
  MetricBar, Gauge, SectionHeader, BeforeAfterSlider (+ zoom/pan Lightbox),
  TabbedPanel, Badge, Skeleton, Reveal and Card. Pages should compose these
  and never add raw hex values.

## Where things come from

- **Settings** come from `configs/base.yaml`: the `frontend:` block, plus
  `sr.scale`, `dataset.bands`, `runtime.max_parameters` and `seed`.
  `scripts/repo-config.mjs` reads them and `vite.config.ts` bakes them in. A
  missing key stops the dev server. Editing base.yaml restarts it.
- **Placeholder imagery** (`public/placeholders/`, gitignored) is generated by
  `scripts/make_placeholders.mjs` on every `dev`/`build`. It is a seeded
  procedural scene at 2.5 m, and its exact 4×4 block mean at 10 m. Both carry a
  burned-in `PLACEHOLDER` mark. The σ layer is an edge map, **not** a model σ.
- **Metrics** (`src/api/fixtures/metrics.json`) are a snapshot of
  `reports/day3_results.json`, with keys unchanged. Refresh it with
  `npm run fixtures:metrics` after the report is regenerated.

## Day 4 contract

`src/api/client.ts` is the only module that calls the network. Its request and
response types are the wire format (snake_case):

| endpoint | request | response |
|---|---|---|
| `GET /health` | — | any JSON with HTTP 200; drives the "Backend: online/offline" badge, probed once per load even in MOCK_MODE |
| `POST /sr` | `SrRequest { bbox }` | `SrResponse` (lr / sr / uncertainty layers + provenance) |
| `GET /metrics` | — | `MetricsResponse` (a subset of `day3_results.json`) |

Paths are relative to `VITE_API_BASE`, default `http://localhost:8000` (the
backend must allow CORS from the dev origin). Switch to the live backend with
`VITE_MOCK_MODE=false`. **The backend must enforce
`frontend.tile.max_tiles` itself, and answer 413 the way the mock does.** The
UI's check only protects the judge from a mistake; it is not a guard.

## Non-negotiables built in

- Every SR view renders `AiBadge`: "AI-RECONSTRUCTED — NOT MEASURED DATA". It
  takes no props, has no close control, and is covered by the e2e test.
- Rasters are drawn with `nearest` resampling. A 10 m pixel stays a 10 m square
  instead of being smoothed to look finer than it is.
